## The problem with v6.15.10

v6.15.10's nuclear restart logic was correct in concept but used the
wrong Quickshell invocation:

```bash
# v6.15.10 (WRONG for Paul's setup)
pkill -f 'qs.*zen-shell'
qs -c zen-shell
```

Paul's actual reload pattern is:
```bash
pkill -f zen-shell
sleep 0.2
quickshell -p ~/.config/quickshell/zen-shell &
```

Different executable (`quickshell` vs `qs`), different arg style
(`-p PATH` vs `-c NAME`). The `pkill -f 'qs.*zen-shell'` pattern
didn't match `quickshell -p ~/.config/quickshell/zen-shell` in
Paul's process list, so v6.15.10's nuclear restart silently failed
to fire at all — which is why Paul reported:

> "hindi nag restart yung mismong qml ko pre quickshell mismo panu
> force restart ?"

## Fix

**1. Broader pkill pattern:** Changed from `qs.*zen-shell` to plain
`zen-shell`. Matches both `qs -c zen-shell` AND `quickshell -p
~/.config/quickshell/zen-shell` (both have "zen-shell" in their
cmdline).

**2. Correct respawn command:** Changed from `qs -c zen-shell` to
`quickshell -p "$HOME/.config/quickshell/zen-shell"` — Paul's exact
invocation.

**3. Helper script approach:** Instead of nested `bash -c "bash -c
'...'"` with escape characters, we now write the restart commands
to `/tmp/zen-shell-nuclear-restart.sh` and execute the script.
Zero quoting issues.

**4. Debug log:** The helper script writes progress to
`/tmp/zen-shell-nuclear-restart.log`. After a nuclear trigger,
check this file to see what happened:
```bash
cat /tmp/zen-shell-nuclear-restart.log
# [2026-04-20T22:17:34-05:00] nuclear-restart: starting
# [2026-04-20T22:17:34-05:00] nuclear-restart: killed old qs
# [2026-04-20T22:17:35-05:00] nuclear-restart: respawn dispatched
```

**5. Recovery timer:** `_nuclearRestartPending` flag now auto-clears
after 3 seconds. If the respawn fails silently, another Float/FW
→ Island cycle triggers a fresh attempt (instead of the flag
getting permanently stuck).

**6. Manual test IPC:** Added `testNuclearRestart` endpoint for
testing the respawn outside the mode-change pathway:

```bash
quickshell -p ~/.config/quickshell/zen-shell ipc call zen testNuclearRestart
```

If this doesn't produce a flicker-then-respawn within ~1 second,
the respawn mechanism has a system-level issue (permissions, PATH,
etc.) and the debug log will tell you why.

**7. Console logging:** Every panel mode change now logs:
```
[ZenShell v6.15.11] Panel mode: floating → island
[ZenShell v6.15.11] Nuclear trigger matched (prev=floating, curr=island) — scheduling restart in 250ms
[ZenShell v6.15.11] Nuclear restart triggered: Float/FW → Island. Dispatching respawn.
```

View via `journalctl --user -f` or if running foreground, directly
in the terminal where quickshell was launched.

## The helper script (generated at runtime)

```bash
#!/usr/bin/env bash
# Auto-generated by Zen Shell v6.15.11 — do not edit
# Respawns zen-shell after Float/FW → Island transition.
exec >> /tmp/zen-shell-nuclear-restart.log 2>&1
echo "[$(date -Iseconds)] nuclear-restart: starting"
sleep 0.3
pkill -f zen-shell
echo "[$(date -Iseconds)] nuclear-restart: killed old qs"
sleep 0.2
quickshell -p "$HOME/.config/quickshell/zen-shell" &
disown
echo "[$(date -Iseconds)] nuclear-restart: respawn dispatched"
```

## The launch chain

```
Quickshell QML engine
  └─ bash (Process element)
       └─ writes script to /tmp
       └─ tries: setsid -f /tmp/zen-shell-nuclear-restart.sh
             (if setsid unavailable)
           └─ nohup /tmp/zen-shell-nuclear-restart.sh & disown
                ├─ sleep 0.3
                ├─ pkill -f zen-shell → (kills Quickshell)
                │      but setsid-detached script survives
                ├─ sleep 0.2
                └─ quickshell -p ... & → new shell launches
```

`setsid -f` forks into a new session. The new session is
independent of Quickshell's process tree. When Quickshell dies
from pkill, the detached script continues running, reaches the
`quickshell -p ...` line, and spawns the new shell cleanly.

## If the nuclear restart STILL doesn't work

Check `/tmp/zen-shell-nuclear-restart.log`:

**If log is empty or missing:** The helper script wasn't written
or executed. Likely causes:
- `/tmp` not writable (very unusual)
- setsid AND nohup both missing (very unusual on Linux)

**If log shows "starting" but no "killed old qs":** pkill didn't
match anything. Test manually:
```bash
pkill -nf zen-shell -v  # -n dry-run, -v verbose
```

**If log shows "killed old qs" but no new shell:** The `quickshell
-p ...` command failed. Test manually:
```bash
cd ~
quickshell -p ~/.config/quickshell/zen-shell
```

**If everything in log looks good but shell visibly didn't flicker:**
Maybe my condition isn't firing. Test via IPC:
```bash
quickshell -p ~/.config/quickshell/zen-shell ipc call zen testNuclearRestart
```

If this works but mode-change trigger doesn't, the issue is in the
PanelState.panelModeChanged connection — check the debug console
for the panel mode transition logs.
